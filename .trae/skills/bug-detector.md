# Bug 检测技能 (Bug Detector)

## 何时使用（When）

当需要检测代码中潜在的 Bug 时使用此技能：
- 代码提交前的 Bug 扫描
- 线上问题排查后的代码检查
- 重构前的风险评估
- 代码审查时的深度检查
- 用户怀疑代码有问题时

**特别适用于**：
- 复杂业务逻辑
- 状态管理代码
- 异步操作代码
- 边界条件处理
- 错误处理逻辑

---

## 如何执行（How）

### Bug 检测清单

#### 1. 空值/未定义问题

| 问题类型 | 检查点 | 代码示例 |
|----------|--------|----------|
| 空指针访问 | 访问可能为 null/undefined 的属性 | `user.name` (user 可能为 null) |
| 可选链遗漏 | 嵌套属性访问缺少可选链 | `user.address.city` |
| 数组空检查 | 访问数组元素前未检查长度 | `items[0].name` |
| 函数返回值 | 函数可能返回 undefined | 缺少 return 路径 |

**检测方法**：
- 查找没有空检查的属性访问
- 检查函数所有路径是否都有返回值
- 检查数组索引访问前的长度验证

#### 2. 类型错误

| 问题类型 | 检查点 | 代码示例 |
|----------|--------|----------|
| 类型强制转换 | 隐式类型转换导致意外结果 | `'5' + 3 = '53'` |
| 严格相等 | 使用 == 而非 === | `if (value == null)` |
| typeof 陷阱 | typeof null === 'object' | `typeof obj === 'object'` |
| 数组类型判断 | Array.isArray vs typeof | `typeof [] === 'object'` |

#### 3. 异步错误

| 问题类型 | 检查点 | 代码示例 |
|----------|--------|----------|
| 未处理的 Promise | async 函数调用没有 await | `fetchData()` (没有 await) |
| Promise 错误丢失 | Promise 没有 catch | `promise.then(callback)` |
| 竞态条件 | 多次异步调用顺序不确定 | 连续状态更新 |
| 内存泄漏 | 定时器/监听器未清理 | setInterval 未清除 |

#### 4. 边界条件

| 问题类型 | 检查点 | 代码示例 |
|----------|--------|----------|
| 除以零 | 分母可能为零 | `total / count` |
| 数组越界 | 索引超出数组长度 | `items[items.length]` |
| 数值溢出 | 数值超过安全范围 | 大数运算 |
| 日期边界 | 时区、闰年、月末处理 | 日期计算 |
| 字符串空值 | 空字符串 vs null vs undefined | `if (str)` |

#### 5. 逻辑错误

| 问题类型 | 检查点 | 代码示例 |
|----------|--------|----------|
| 运算符优先级 | && 和 || 优先级混淆 | `a && b || c` |
| 赋值 vs 比较 | if 中使用 = 而非 == | `if (user = admin)` |
| 循环条件错误 | 死循环或提前终止 | `for (let i = 0; i <= length; i++)` |
| 函数副作用 | 函数修改了输入参数 | 修改对象参数属性 |
| 状态不一致 | 多步操作中间失败导致状态不一致 | 部分更新 |

#### 6. 错误处理缺陷

| 问题类型 | 检查点 |
|----------|--------|
| 吞掉错误 | catch 块为空或只打日志 |
| 错误信息丢失 | 重新抛出时丢失原始错误 |
| finally 中的错误 | finally 中的异常覆盖 try 中的异常 |
| 错误类型错误 | 抛出 Error 字符串而非 Error 对象 |

### 检测流程

1. 阅读代码，理解业务逻辑
2. 按照上述清单逐项检查
3. 标记发现的问题，按严重程度分类
4. 提供修复建议和代码示例
5. 验证修复方案的正确性

---

## 产出什么（What）

产出一份 Bug 检测报告，包含：
1. 问题总览（按严重程度统计）
2. 详细问题列表，每个问题包含：
   - 问题描述
   - 位置（文件:行号）
   - 严重程度（严重/重要/一般/提示）
   - 问题代码
   - 修复建议
   - 修复后的代码示例
3. 修复优先级建议
4. 预防此类 Bug 的最佳实践

### 严重程度定义

| 级别 | 定义 | 示例 |
|------|------|------|
| 🔴 严重 | 必然导致功能异常或崩溃 | 空指针、未处理的异常 |
| 🟠 重要 | 特定条件下导致功能异常 | 边界条件、竞态条件 |
| 🟡 一般 | 不影响功能但可能导致意外行为 | 类型转换、运算符优先级 |
| 🔵 提示 | 代码质量问题，潜在风险 | 代码风格、可维护性 |
